Этот чек-лист фиксирует результат первого прогона на iPhone и сценарии, которые команда ещё подтверждает вручную. Ветка для прогона — [integration/biletflow-e2e](https://github.com/IliyasNU/palantir/tree/integration/biletflow-e2e).

## Подготовка

1. Запишите SHA ветки и запустите API на отдельной тестовой PostgreSQL по [инструкции проекта](https://github.com/IliyasNU/palantir/blob/integration/biletflow-e2e/README.md). Проверьте `alembic current` → `0002 (head)` и `/health` → HTTP 200, `status: ok`, `database: up`.
2. Укажите реальные адреса API в `VITE_API_URL` и `EXPO_PUBLIC_API_URL`. При запуске web на том же компьютере пример API — `http://127.0.0.1:8000`. Для телефона укажите LAN-адрес компьютера, откройте `/health` с телефона и проверьте, что телефон и компьютер в одной Wi-Fi сети. Для опубликованного web используйте доступный HTTPS API и добавьте точный origin web в `CORS_ORIGINS`.
3. Запустите Vite и Metro. Для физического iPhone войдите в Expo CLI и Expo Go SDK 58 одним аккаунтом Expo. На Windows подходят команды `npx.cmd expo login`, `npx.cmd expo whoami` и `npx.cmd expo start --go --lan`. [Инструкция Expo](https://docs.expo.dev/troubleshooting/expo-go-sign-in-required/)
4. Подготовьте отдельные аккаунты организатора, двух посетителей и сотрудника. Опубликуйте тестовое событие, назначьте сотрудника и подготовьте ещё одно событие с одним местом. Для проверки прав понадобится пользователь без назначения. Для первого прогона используйте свежий билет и держите web-страницу билета на отдельном экране.

## Сквозной сценарий · Санжар и Ильяс

1. В web получить новый билет и открыть его QR из «Мои билеты».
2. На телефоне проверить соединение, войти сотрудником, выбрать назначенное событие и отсканировать QR с экрана web. Ожидается «Вход подтверждён» и одна запись в `check_ins` по `ticket_id`.
3. Нажать «Следующий билет» и отсканировать тот же QR. Ожидается «Этот билет уже использован», код `ALREADY_CHECKED_IN`. По тому же `ticket_id` сохраняется одна запись.
4. Повторить на физическом Android. Для iPhone этот прогон дополнит уже подтверждённую проверку через PNG сквозной проверкой именно web-интерфейса.

## Как зафиксировать результат

Для каждого сценария укажите дату, проверяющего, SHA, ОС и версию браузера или Expo Go, окружение, результат **прошёл / сбой / не проверено** и подтверждение. Для web достаточно статуса HTTP и скриншота состояния. Для check-in приложите ID события и билета, `request_id` и число записей в `check_ins`. Из скриншотов и логов удалите пароли, токены, `.env` и содержимое QR.

Перед показом подтвердите сквозной сценарий на выбранном устройстве и устраните блокирующие сбои. Если на защите требуется Android, нужен отдельный результат на Android. Для ручного поиска посетителя и счётчиков участников backend предоставляет `GET /events/{id}/attendees?q=` и `GET /events/{id}/attendance` (см. [контракт mobile](../mobile/API.md)); экраны mobile для них ещё не сделаны. Отмена check-in остаётся открытым требованием SRS; её статус и сроки экранов mobile команда согласует отдельно.
